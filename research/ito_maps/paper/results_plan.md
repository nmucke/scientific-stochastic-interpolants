# Final results integration plan

The manuscript now inputs `results.tex` for the results narrative. This file currently contains clearly labeled preliminary validation results. The appendix table is generated by `paper/build_validation_table.py` from six matched source JSON artifacts, with source hashes recorded in `paper/generated/validation_sources.json`. Held-out testing has not yet started as of this revision. `experiments/report_results.py` creates auditable tables and quality/cost figures from saved evaluations and checks matched cases, split, ensemble size, coordinates, and horizon. `experiments/paired_comparison.py` computes paired comparisons.

Current training method is **two-stage teacher distillation**: 2,000 teacher-diagonal PSD updates, then 500 same-path 32-step teacher-rollout updates. Use the actual selected model checkpoint and executed history when populating final rows. Do not describe refined maps as trained wholly without simulation. First-stage checkpoints can be an ablation, not silently conflated with the refined maps.

Main results should show the full useful 1/2/4/8 map frontier with matching solver baselines and a sufficiently resolved solver budget. Keep CRPS as primary, energy/RMSE as secondary, and report measured end-to-end ensemble latency plus NFE. Identify explicit comparison pairs. If map quality is measurably worse than SI64, quantify the loss and speed gain; comparison with a coarser SI16 alone cannot imply equivalence to the best baseline.

Calibration: use randomized ranks, finite-ensemble corrected RMS spread if recorded, and empirical coverage with the appendix caveat. Legacy mean-pixel-std spread remains available for compatibility but is not an exact ratio-one criterion. Spectrum errors compare predicted mean spectrum to a single target spectrum unless conditional reference ensembles exist.

Final evidence sources must be held-out test artifacts with frozen configuration/checkpoint provenance. Validation pilot measurements (four trajectories, eight ensemble members) remain development evidence. The conditioned same-path Navier–Stokes compression diagnostic and analytic linear-SDE calculation are methodological diagnostics, not independent test benchmark scores. A single training seed limits generality even when trajectory CIs are narrow.

Mainpaper figure/table layout is sketched in comments in `results.tex`. Prefer uncertainty on paired differences over inference from overlap of individual CIs. Build with `make -C research/ito_maps/paper` after incorporation and inspect PDF overflow, labels, and anonymous formatting.


## Artifacts needed for the final integration

1. Configuration-freeze manifest: chosen map checkpoint paths/hashes and training-stage labels; teacher paths/hashes; final ensemble size, origins, trajectories, sampling budgets, seeds, and one-step/ten-lead specifications.
2. Completed one-interval `evaluation.json` files for both teachers and both selected maps, including raw matched trajectory/origin rows and inference timings.
3. Completed ten-lead autoregressive `evaluation.json` files for the selected comparison budgets, preserving physical lead labels and raw rows. Confirm history updates contain each member's own predictions.
4. Paired trajectory-bootstrap differences and quality/cost reports generated from those exact artifacts; selected sample/spectrum/rollout figures with provenance.
5. Final student training histories and metadata for both stages (including the flow-rollout run), selected update/epoch, complete wall-time totals, parameter counts, and final source revision.
6. Completed Navier–Stokes same-path compression diagnostic, with reference teacher integration budget, conditioning/bridge sampling scheme, selected validation contexts, and limitations; treat it separately from test-quality results.

The final paper must preserve the observed fact that deterministic flow maps currently have better one-step validation CRPS. It should test whether that persists, not assume an Itô advantage. Only report ten-lead conclusions after those artifacts exist.


## Compression diagnostic and confirmation update

Source hash is in `generated/compression_source.json`. Its estimates motivate K=4 versus K=16 refinement under the same 500-update teacher-rollout budget; they are not forecast-quality guarantees.

Complete student replications with seeds one and two are planned after feature selection; do not label them completed or report three-seed statistics before their artifacts exist. The present validation table remains seed zero only. The teacher 64-vs-128-step sensitivity check is also required before calling the reference converged.
